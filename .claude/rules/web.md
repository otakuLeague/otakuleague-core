# Web with the API (moved from CLAUDE.md)

- The web app copies its own variables (`WEB_ENV_VARIABLES` in `next.config.ts`) from the repo-root `.env`, inside the repo only; real env vars win. It needs `API_BASE_URL` (server-only, example value in `.env.example`; an older `.env` needs it added) and reads `INTERNAL_API_KEY` (server-only, optional: empty locally). A missing or invalid value fails the first API call with one message naming the variable, never its value.
- Internal key and client IP (ADR 0019, OTA-182 slice 2): with `INTERNAL_API_KEY` set, `apiClient()` sends `X-Internal-Api-Key` on every call; `next.config.ts` (`checkInternalApiKeyConfig`) fails the build, and `createApiClient` throws, unless the key is valid and `API_BASE_URL` is https or exactly `127.0.0.1`/`[::1]` (not `localhost`: a name is resolved); unset, nothing changes. `X-Client-Ip` goes only with the key and only on calls that can call AniList for the visitor: the two imports (`loadAnime`, `loadAnimeByAnilistId`) and the list loader (`loadAnimeListPage`, so `/season` and the home rows; OTA-195), all in `src/anime/data.ts`: they pass `clientIp: await readClientIp()` (`src/api/client-ip.ts`: Vercel's `x-forwarded-for`, one address or nothing, and nothing at all unless `VERCEL=1`, since only Vercel overwrites that header; off Vercel the API counts its shared `unknown` visitor). Credential calls send it too, from `readCredentialClientIp()` (next bullets). A CDN or proxy in front of Vercel needs its own decision before it ships. Other loaders and `proxy.ts` never call `headers()`, which would add request-time data to a page. `clientIp` on a cached call (`next.revalidate`, `cache` other than `no-store`) throws: it would split Next's data cache per visitor. A loader that passes `clientIp` must never be wrapped in `'use cache'` (`headers()` cannot be read there, and the IP would be cached for everyone). A list loader wrapped in `'use cache'` later must not send it (see ADR 0019, OTA-195). Every loader exported by `data.ts` must be in one of the two lists of the `data.test.ts` rollout gate (the test fails otherwise); one that can call AniList for the visitor passes `clientIp`. Never `NEXT_PUBLIC_INTERNAL_*` or the `env:` block of `next.config.ts` (`config.test.ts` checks both).
- Session and credential calls (ADR 0003 OTA-139 addendum): `call(path, { session })` takes only a `SessionToken` from `sessionTokenFrom()` (`src/api/session-token.ts`, 43 base64url characters) and sends `Authorization: Bearer` next to the key; a call that posts a password or an emailed token sets `requiresInternalKey: true`. Without `INTERNAL_API_KEY` either one throws before any request (never dropped: a dropped Bearer would sign members out). `session` or `requiresInternalKey` on a cached call throws, like `clientIp`; that check cannot see a `'use cache'` scope, so a session or credential call is never made inside `'use cache'`. A 429 envelope carries `retryAfterSeconds` (1 to 86,400) only from a whole-seconds `Retry-After`. There is no free-form `headers` option. `WEB_PUBLIC_URL` (`readWebPublicUrl(env)`, `src/auth/web-public-url.ts`) is read on first auth use, never at build: exactly an origin (a trailing `/` allowed), https, or http only for `localhost`, `127.0.0.1`, `[::1]` and never when `VERCEL=1`.
- Auth server code (OTA-139 1f-ii): auth actions and helpers live in `src/auth/`. Every call that posts a password or an emailed token goes through `credentialCall({ path, body, isExpectedBody })` (`src/auth/credential-call.ts`), one of the two auth files allowed to import `apiClient()` (with `session-call.ts`, below): a lint gate in `eslint.config.mjs` bans `apiClient`/`createApiClient` imports in `src/auth/**` and `app/auth/**` (type imports stay allowed; `network-lint-rule.test.ts`). It refuses before any request on Vercel without `VERCEL_ENV=production` (`preview_deployment`) and when the IP is unknown (`client_ip_unknown`: `x-forwarded-for` missing or malformed, which the calling action reports to Sentry, never with an IP; `action_forwarded`: `x-action-forwarded`, a Server Action hop Next re-sent between workers, never reported since a visitor can send it), else sends exactly one uncached POST with the key and `X-Client-Ip` from `readCredentialClientIp()` (`src/api/client-ip.ts`: Vercel's `x-forwarded-for`; off Vercel 127.0.0.1 for an http `WEB_PUBLIC_URL` and a configuration throw for https; the header is never read off Vercel). Never retried. `sessionCookie(webPublicUrl)` (`auth-cookies.ts`) gives the cookie name and attributes and `clearedSessionCookie(webPublicUrl)` the same with `Max-Age=0` for `cookies().set(name, '', options)`: never `cookies().delete()` for the session cookie (it sends no `Secure`, so a browser ignores it for `__Host-`); `safeNextPath(next, webPublicUrl)` (`safe-next-path.ts`) is the only way to turn `next` into a redirect. Every auth Server Action calls `isSameOrigin(origin header, webPublicUrl)` (`web-public-url.ts`) before reading its FormData, and refuses otherwise (login CSRF; Next itself only aborts a `null` or foreign-host `Origin`). No page may be served with `Referrer-Policy: no-referrer` (a native form POST would then send `Origin: null`, and the header's sign-out form is on every page): keep `strict-origin-when-cross-origin`. The referrer guard (`src/auth/referrer-policy.test.ts`, ADR 0015 Addendum 1f-iv-c2) fails if any non-test file of apps/web (any extension, `node_modules`/`.next` skipped) holds that literal in any case, or the legacy quoted `never` value after "referrer"; sources say "the referrer guard" instead. Every route carries `FRAME_DENY_RULE` (`src/auth/frame-headers.ts`: `Content-Security-Policy: frame-ancestors 'none'` and `X-Frame-Options: DENY` on `/:path*`, after the robots rules in `next.config.ts` `headers()`; `config.test.ts` checks the wiring): no page renders in a frame.
- Sign-in action (OTA-139 1f-iii-a): `signInAction(previousState, formData)` (`src/auth/sign-in-action.ts`, `'use server'`, exports only the action, ignores the previous state, no try/catch) returns a `SignInFormState` from `sign-in-form-state.ts` (pure, never holds what was typed). Previews answer `off_on_preview` before the form is read, then a request whose `Origin` is not exactly `WEB_PUBLIC_URL`'s origin (`isSameOrigin`, `web-public-url.ts`; missing or `null` included: login CSRF) gets `unavailable`, unreported; `readSignInFields` (a FormData, both fields non-empty strings kept as typed, identifier ≤ 254 and password ≤ 1024 UTF-16 units: `IDENTIFIER_MAX` and `PASSWORD_RAW_MAX` from `@otakuleague/shared-types`, the very constants the API's DTOs check) else `invalid_credentials` with no call; then one `credentialCall`, mapped by `signInOutcomeFrom` on the error code only (`AUTH_BUSY` drops its Retry-After, anything unknown is `unavailable`). Only a success sets the session cookie (`sessionCookie()`) and then calls `redirectTo(safeNextPath(next))`; `redirectTo` (`redirect-to.ts`) takes only the `SafeNextPath` brand. `client_ip_unknown` calls `reportClientIpUnknown(route)` (`auth-reports.ts`, server only, never in `src/observability/sentry.ts`): a Sentry error with only the `auth_route` tag (never a tag key matching `credential`, `token`, `session`…: the scrubber masks it) and a fixed fingerprint, at most once per instance every 10 minutes, flushed in `after()`. A called and failed sign-in goes through `authCallFaultOf`, and only a fault is reported (`reportAuthCallFault('sign-in', fault)`): never the visitor's input (wrong password, validation, 429, `AUTH_BUSY`) or an outage (ADR 0015 Addendum 1f-iv-b2).
- Sign-in page (OTA-139 1f-iii-b): `/auth` (`app/auth/page.tsx`) keeps its h1 and form in the static shell (ADR 0014: no API call, no `headers()`/`cookies()` at render); only `AuthQueryFields` (`app/auth/auth-query-fields.tsx`, inside `Suspense`) awaits `searchParams`: `next` goes into a hidden field exactly as sent (`rawNextParam`: one string of 1–2048 characters; validation only in the action), and `mode` from `parseAuthMode()` (`src/auth/auth-mode.ts`: exactly `signup`/`sign-up`, else sign-in) shows the sign-up-closed note. A preview deployment (`credentialRoutesOff`) renders `PreviewOffNotice` and no password field. `SignInForm` (`src/auth/sign-in-form.tsx`, client) holds `useActionState` and the last submitted identifier (read from the FormData on submit), given to the field as `defaultValue`: both fields stay uncontrolled (typing or autofill before hydration survives), and React's reset after a failure restores the identifier and clears the password. The alert is hidden while pending, so a repeated failure is announced again. With JavaScript, `redirectTo` replaces the history entry (the no-JS 303 path ignores it). `/sign-in` answers a 308 to `/auth?mode=sign-in` (`LEGACY_AUTH_REDIRECTS`, `next.config.ts` `redirects`; per Next's docs the query passes through and the destination's `mode` wins: a beta check, not verified). `logging.serverFunctions: false` keeps Server Action arguments (could include credentials) out of the dev log.
- Session core (OTA-139 1f-iv-a, ADR 0015 Addendum 1f-iv): every call carrying a member's session goes through `sessionCall({ session, path, method?, isExpectedBody?, timeoutMs? })` (`src/auth/session-call.ts`, the second and last auth file the lint gate lets import `apiClient()`): a `SessionToken` only, GET or POST, key and Bearer, never `X-Client-Ip` or a body, `no-store`, one attempt; `preview_deployment` (`credentialRoutesOff`) refuses before any request, then `await connection()`, so it throws in a cache scope (`'use cache'`); a missing key throws. `readSessionToken(webPublicUrl)` beside it is the only reader of the session cookie's value (`__Host-` name on https only, `sessionTokenFrom` else nothing). `loadViewer()` (`load-viewer.ts`) never throws but Next's signals: preview → `signed_out`, then `await connection()` (a prerender stops there), then neither session cookie name present (`hasSessionCookie()`, `SESSION_COOKIE_NAMES` in `auth-cookies.ts`, presence only) → `signed_out` before `WEB_PUBLIC_URL` is read, then no or malformed token under the configured name → `signed_out` with 0 calls, else one `GET /me` (`isMeResponse`, 2,000 ms) mapped by pure `viewerFrom` (`viewer.ts`: valid 200 → `signed_in`, only a 401 `UNAUTHORIZED` envelope → `signed_out`, anything else `unavailable`); a throw goes through `unstable_rethrow` first, then is reported as `configuration` and `unavailable`. It reads cookies, never sets or deletes one. Its one caller is `ViewerActions` in the header's `Suspense` (iv-c). Faults (`authCallFaultOf`: 403 `INTERNAL_KEY_REQUIRED`, `invalid_response` under 500) go to `reportAuthCallFault(route, kind)` (`auth-reports.ts`; `AuthReportKind` = a fault or `revocation_unconfirmed`): `auth_route` and `auth_fault` tags and a fixed fingerprint per kind only, one throttle per kind (10 min), flushed in `after()`, never thrown. In a cache scope `sessionCall` throws and `loadViewer` reports `configuration`: neither belongs in `'use cache'`.
- Session lifecycle (OTA-139 1f-iv-b, ADR 0015 Addendum 1f-iv-b): `deleteSession(session)` (`src/auth/delete-session.ts`) is the only caller of `POST /auth/sign-out`: one `sessionCall`, 2,000 ms, never retried, total like `loadViewer` (204 with no body, a 401 `UNAUTHORIZED` envelope or a preview refusal: silent; a 2xx with a body is `invalid_response`; any other failed answer: one report as route `sign-out`, the fault or else `revocation_unconfirmed` (timeout, network, 429, 5xx, another 4xx); a throw: `configuration` after `unstable_rethrow`). Never export it from a `'use server'` file (every export is a public endpoint). `signOutAction(): Promise<SignOutFormState>` (`sign-out-action.ts`, `'use server'`, takes no input; `SignOutFormState` = `idle | refused | failed` in `sign-out-state.ts`; its one caller is `SignOutForm` in the header's account menu): preview → `refused` before `WEB_PUBLIC_URL` is read; `isSameOrigin` fails → `refused` with no cookie read, call, write or redirect; it never answers `failed`; a well-formed cookie → `deleteSession`; always `cookies().set(name, '', options)` from `clearedSessionCookie` (never `delete()`); then `redirectToSignedOut()` (`redirect-to.ts`, constant `/`, replace). `signInAction` reads the old token after the form check and only on success calls `deleteSession(old)` before setting the new cookie (a failed sign-in keeps the old session).
- Redirect and dynamic import gates (OTA-139 1f-iii-c, ADR 0015 Addendum 1f-iii-c): `no-restricted-syntax` in `eslint.config.mjs` bans value imports of `redirect`/`permanentRedirect` from `next/navigation` (named, aliased, string-named, `default`, namespace, default import, re-exports, `next/navigation.js`, any path ending in `/next/navigation`) and anything from `next/dist/` everywhere in apps/web. Only `src/auth/redirect-to.ts` (`redirectTo`, a `SafeNextPath` only) and the anime slug helpers (`resolve-tab.ts`, `season-redirect.ts`: `tabHref()` on a canonical slug checked with `CANONICAL_SLUG_PATTERN`) may use a named import; re-exports and next/dist stay banned there too. A new redirect goes through one of them; the signed-out redirect of 1f-iv is a second helper inside `redirect-to.ts`, never a fourth file. Type-only imports are fine. `import()` everywhere, those three included, must take a string literal and never load `next/navigation`, `next/dist/`, a specifier ending in `api/client` (inside `src/api`, `import('./client')` stays allowed) or a network module (`NETWORK_IMPORTS`). `require()` is `@typescript-eslint/no-require-imports`. `noInlineConfig` makes `eslint-disable` inert in every non-test file. Lint cannot see (never use these to step around a gate): `NextResponse.redirect`/`Response.redirect` (route handlers, `proxy.ts`; 1f-vi), client-side navigation (`useRouter().push`, `window.location`), `createRequire`, `eslint-disable` in tests, path variants (`next/./navigation`, `../api/./client`; the session cookie gate below matches the last segment, so `./session-call/../session-call` is caught), an `apiClient`, `hasSessionCookie` or `SESSION_COOKIE_NAMES` aliased or wrapped after import, a re-export or wrapper of either name written inside `load-viewer.ts` or `session-call.ts`, an `import()` followed by a property read (`(await import('./session-call')).hasSessionCookie`). Rows in `network-lint-rule.test.ts`.
- Session cookie gate (OTA-139 1f-iv-c3, ADR 0015 Addendum 1f-iv-c2 decision 7): `no-restricted-imports` patterns (`SESSION_COOKIE_GATE` in `eslint.config.mjs`) let only `src/auth/load-viewer.ts` import `hasSessionCookie` (`session-call.ts`) and only `src/auth/session-call.ts` import `SESSION_COOKIE_NAMES` (`auth-cookies.ts`); named, aliased, type-only, namespace and re-export forms are refused everywhere else, `src/api/client.ts` and tests included. Each exception is a one-file block that restates every option of the rule and frees one name. Tests reach either name with `await import()`; a rename of either export or file must update the gate (a pin in `network-lint-rule.test.ts` fails first).
- Restart `pnpm dev` after editing the root `.env`, and don't add `apps/web/.env*` files (ADR 0003).
- Anime pages (OTA-97): `/anime/[slug]` and its six tab routes (`/episodes`, `/cast`, `/music`, `/related`, `/stats`, `/community`). `apps/web/proxy.ts` (matcher `/anime/:path*`) calls `GET /anime/slugs/:slug/resolve` (300 ms timeout, answers cached about 60 s) and answers another slug or letter case with a 308 to the canonical slug on the same tab, and an unknown slug with the anime 404 page and a real 404 status. It has to be the proxy: with Partial Prefetching, Next sends a prerendered App Shell (status 200) before a page can resolve its slug. When the API is slow or down the proxy lets the request through and the page shows its own state. Check with `curl -I localhost:3000/anime/<alias>/cast`.
- Anime links (ADR 0018, OTA-191): every link to an anime page goes through `animeLink(entry, segment?)` (`src/anime/anime-link.ts`): `/anime/<slug>` with no rel only when `imported === true` and the slug is non-null (a missing flag from an older API means not imported); anything else is the `/anime/anilist/<id>` route with `rel="nofollow"` (slugs are claimed before import since OTA-190, so a followed slug link would cold-import).
- Season selector (OTA-97): `season-selector.tsx` (client, disclosure of links, not a listbox) gets the main line trimmed by `seasonOptions()` in `src/anime/tabs.ts`; shown whenever the main line has 2+ seasons, hidden otherwise (one season, `unavailable` or a franchise failure, 2 s timeout). Every season is a link that keeps the tab (`animeLink(season, segment)`, `prefetch={false}`); a season not imported yet (a claimed slug is not enough) links to `/anime/anilist/[id]/[[...tab]]` with `rel="nofollow"`.
- AniList id route (OTA-172): `app/anime/anilist/[id]/[[...tab]]` runs `seasonRedirect()` (`src/anime/season-redirect.ts`): validates id and tab (else 404 with no API call), calls `GET /anime/anilist/:id` (imports on first visit, 15 s timeout), then a 307 to the canonical slug on the same tab. API 404/400 or a null `canonicalSlug` → not found; an outage or timeout throws (error page). Not blocking: `loading.tsx` streams the anime page's `HeaderLoading`, so on a direct hit both outcomes are streamed, never a real 307/404 status: HTTP 200, then a meta refresh to the slug or the not-found UI. Client navigations from the selector just redirect. A slug that is not well formed throws (outage path). Always noindex: `robotsHeaders()` sends `X-Robots-Tag` on `/anime/anilist/:path*` even when indexing is allowed, and the slug proxy ignores these paths.
- Anime header (OTA-97): every value comes from `headerFacts()` (`apps/web/src/anime/header-facts.ts`), which hides what AniList lacks; add a header value there, with a test, not in the component. Accent text colours come from `accentPalette()`; a new chip colour goes in `tokens.css` (dark block and both light blocks) and in `CHIP_TOKENS` of `app/styles/tokens.test.ts`, which fails under 4.5:1. `next/image` runs with `images.unoptimized`: cover URLs from any source CDN render as-is, nothing is cached here.
- Overview tab (OTA-100, design `docs/design/overview-tab/`): `OverviewLoader` in `app/anime/[slug]/overview.tsx` reuses the request-cached `loadAnime()` (no extra API call) and renders nothing on failure or redirect (the header owns those states). Values come from `overviewFacts()` (`src/anime/overview-facts.ts`, built on `headerFacts()`); empty rows and an empty Details card are hidden. The synopsis is plain text rendered as React text (never `dangerouslySetInnerHTML`); the server decides if it collapses (>350 chars or >1 paragraph), and `synopsis.tsx` is the only client island (a `<noscript>` style un-collapses it without JS). Only an AniList synopsis is shown: MyAnimeList text waits on OTA-127 (ADR 0006). Slice 1: synopsis, details, genres (plain chips until browse routes exist).
- Motion and glass (OTA-150): transitions use the `--ease-*` / `--dur-*` tokens in `app/styles/tokens.css` (when to use each: `docs/design/system-v2/motion.md`), move things with `transform`/`opacity` only (colour and shadow transitions on small elements are fine), and each component states its `prefers-reduced-motion` behaviour. Frosted surfaces only through `.ol-glass` (solid fallback built in); never animate the blur.
- Global shell (OTA-152, design `docs/design/global-shell/`, ADR 0014): `app/layout.tsx` renders the static background (`.sh-bg`), `SiteHeader` and `SiteFooter` on every route; styles in `app/styles/shell.css`, `--brand-a/--brand-b` and `--header-h` in `tokens.css`. Header menus are native `<details name="sh-menu">` through `Disclosure` (`src/shell/disclosure.tsx`: React holds no open state, the enhancer only closes on Esc, outside pointer, focus leaving, link click); a list of links that opens in place is `<details>`, anything that traps focus or is an ARIA composite is Base UI. Nav links and active section by whole path segment in `src/shell/nav.ts` (`activeSection`); `HeaderNav` reads `usePathname` inside a `Suspense` whose fallback is `HeaderNavView pathname={null}`, so the root layout stays static. Search is a plain `GET /search?q=` form until OTA-98. `html, body` use `overflow-x: clip` (hidden breaks the sticky header); fixed bars sit at `top: var(--header-h)`. Below 1100 px (`--bp-lg`, media query 1099.98px) the header search box is hidden so the nav and guest actions fit; below 768 px the header shows logo + Sign in, or the avatar, until the mobile sheet slice. The viewer slot (ADR 0015 Addendum 1f-iv-c, `src/shell/viewer-actions.tsx`): `div.sh-right` is one grid cell holding `GuestActionsSizer` (aria-hidden, `visibility: hidden` spans from `GUEST_ACTIONS`, so no state shifts the header) and a `Suspense` (fallback `ViewerFallback`: the guest links inside `<noscript>`) around async `ViewerActions` = pure `ViewerActionsView`: `signed_out` guest links, `unavailable` nothing, `signed_in` a `Disclosure` (`summaryLabel` the constant "Account menu", never the username: Sentry click breadcrumbs record `aria-label`; summary `viewerInitials()`, panel starts with the username, end-aligned). `SiteHeader` stays synchronous and never takes the viewer as a prop. The panel ends with `SignOutForm` (`src/auth/sign-out-form.tsx`, ADR 0015 Addendum 1f-iv-c2): `useActionState(signOutAction)`, one "Sign out" button and no field, `aria-disabled` while pending with a second submit cancelled (never `disabled`: focus would leave the open menu); `refused` or `failed` shows `role="alert"` "Could not sign out" after the button, hidden while pending. The export is a class error boundary: `getDerivedStateFromError` calls `unstable_rethrow` (the success redirect passes to Next), then mounts the form again in `failed` with the button `autoFocus`ed, so it works without a reload and never reaches `global-error`; nothing is reported from the browser. Styles `.sh-menu__form`, `.sh-menu__action`, `.sh-menu__alert`. Menu panels are solid `--surface`, not `.ol-glass` (a backdrop-filter nested in the header's glass does not blur). Links to routes that don't exist yet use `prefetch={false}`; the account menu's links (Profile, My List, Settings, theme, XP), sheet, 404/500 restyle and hiding the shell on `/auth*` and `/onboarding` are the next OTA-152 slices.
- Theme (`src/shell/theme.ts`): System / Light / Dark in the `ol-theme` cookie (System clears it). Media queries use 767.98px for `--bp-md` (custom properties don't work in media queries).

- Search indexing (OTA-134): the beta is noindex through `SEARCH_INDEXING` in `apps/web/src/seo/indexing.ts` (root `metadata.robots`, plus an `X-Robots-Tag` header on all routes from `headers()` in `next.config.ts`; a test fails if another file under `app/` sets `robots`). robots.txt comes from `app/robots.ts` via `robotsRules()` in `src/seo/site.ts`: only `Disallow: /anime/anilist/` (OTA-173: a crawler following season links would import every season) and `Disallow: /season?` (OTA-137, until OTA-189), plus a `Sitemap:` line only when `'allowed'`; a test checks both and that there is no bare `Disallow: /`. `app/sitemap.ts` lists static pages only (/, /faq, legal pages): anime pages are imported on demand and there is no DB-only list endpoint (ADR 0018). `SITE_URL` (constant: beta and prod are the same build) feeds `metadataBase`, so every page canonical is absolute on otakuleague.com; a test fails if a `page.tsx` has no canonical (directly, `legalMetadata` or `tabMetadata`) outside anime-not-found, debug and anime/anilist. - React review checklist (OTA-185): applies to every `apps/web` diff; whoever writes it follows it, `code-reviewer` checks it item by item on new or changed lines. ESLint (`core-web-vitals`) already catches some hook and key mistakes; look for what lint cannot see.
  - `useEffect` used to copy or compute data → compute during render (or `useMemo` if measured).
  - Server data fetched in the browser (`useEffect`, client `fetch`) → Server Component, or a query hook where "Browser data" below allows one; `useQuery`/`useMutation` called in a component → its own hook file; a query hook used without pending, failed and data states → render all three.
  - Hooks inside conditions, loops or after an early return → move them to the top level.
  - One big component with many boolean/config props → composition (small components as children).
  - State kept higher than needed → smallest useful scope (component, flow, page).
  - Styling outside the system: raw colours instead of tokens; raw px for spacing or radius where a `--space-*`/`--radius-*` token exists (font sizes, 1–2 px borders and outlines, fixed control heights and media queries stay px); inline styles for layout.
  - Stylesheets: new rules in `globals.css`, or unprefixed or bare-element selectors → a feature stylesheet with its own class prefix (`.ov-`, `.in-`, `.sh-`), as existing pages do.
  - New physical CSS properties (`margin-left`) where a logical one works (`margin-inline-start`); `left: 50%` paired with `translateX` stays physical.
  - List `key` from the index or `Math.random()` on a list that can reorder or filter → key from a domain id.
  - Animating anything but `transform`/`opacity` → change it (exceptions in "Motion and glass" above and ADR 0011).

## Browser data (ADR 0017)

- Default stays a Server Component; a form that ends in a navigation is a Server Action. A query or mutation hook only for data that depends on typing, scrolling or a press that must feel instant. Slice 1 (OTA-184) is the rule only: `@tanstack/react-query`, the provider, `browserApiClient()` and the first hooks land with OTA-142, so add none of them before that PR.
- Path: component → hook → `browserApiClient()` (`src/api/browser-client.ts`: `createApiClient` on `<origin>/api`, 8 s timeout) → `app/api/<area>/…/route.ts` → `apiClient()` → API. No CORS, no token in JS, `fetch` still only in `client.ts`, which keeps only the isomorphic factory; `apiClient()` and the `session`, `clientIp` and internal-key options live in a `server-only` file and are not on the browser client's type.
- Handlers: one per call, never a catch-all `[...path]`; a GET never changes state and every non-GET handler calls `assertSameOrigin()`. Answers go through one helper, `private, no-store`: API status and rebuilt envelope (`Retry-After` kept on 429), `invalid_response` 502, `network` 503, `timeout` 504; own refusals 400 `VALIDATION_FAILED`, 401 `UNAUTHORIZED`, 403 foreign Origin. The client IP comes only from Vercel's `x-forwarded-for`, never from a browser header or body; the API honours `X-Client-Ip` only with a valid `X-Internal-Api-Key`; without the key nobody is counted per visitor, and once the key is set such a request is refused (ADR 0019).
- One file and one hook per API call in `apps/web/src/api/<area>/`: `use<Thing>Query.ts`, `use<Thing>InfiniteQuery.ts`, `use<Action><Thing>Mutation.ts`; components never import `@tanstack/react-query`. Keys only through `use<Thing>Query.getQueryKey(params)` (`[area, thing, params]`). A mutation hook invalidates what it changed with those keys, inside the hook, and returns the promise from `onSettled`.
- Failures: one helper wraps `queryFn`/`mutationFn`, turns a failed `ApiResult` into a thrown `ApiFailureError` inside the hook only, and rethrows any other error unchanged. Components read errors through the `instanceof` helper, never assume `error.failure`, and render pending, failed and data. Hooks pass an `isExpectedBody` guard. No `throwOnError`, no `useSuspenseQuery`.
- Each query names its kind: `suggestion` 60 s, `catalogList` 5 min, `viewerList` 30 s (no focus refetch for these three), `viewerEntity` 30 s (focus refetch on). Retry at most 2, only on 500 and 503; mutations never retry.
- Session: keys carry no viewer, so the cache is cleared (`queryClient.clear()`, running mutations cancelled) on sign-in, sign-out and any 401 from a member route.
- Never copy `query.data` into `useState` with `useEffect`: render `query.data`, state holds only the user's draft. A value a mutation can change has one owner, its hook (seeded with `initialData` from the server); if a Server Component shows it too, the mutation hook calls `router.refresh()`.
- Optimistic writes (+1 episode): send the resulting value, `onMutate` snapshot + `setQueryData`, `onError` restore, invalidate when the last mutation for that entry settles, `scope: { id }` per entry. Failure shows inline with Retry (My List design), no animation on the number.
