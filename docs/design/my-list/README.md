Mockups for `/my-list` and the add-to-list control, built by OTA-142. Open the `mockup-*.html` files in a browser (static, no JS); screenshots at 1440 and 390 px are in `shots/`. ## Direction
- Make "what am I watching, and what's next" one glance and one tap: progress sits on every card and row, and in-progress entries (Watching, Rewatch, On hold) get a +1 button.
- Hierarchy: status tabs with counts → search/sort/view → entries (cover, title, progress, your score, favourite).
- The memorable moment: finishing a show (gold "+XP" chip rising from the control, level bar filling in a toast). Nothing else celebrates.
- Removed: the drag-and-drop board, the silent empty-on-error state, the always-loaded full list.

## Decisions
- **Board dropped.** The old kanban (dnd-kit) is replaced by status tabs that keep every status visible with its count (including 0, like the old empty columns). Reasons: at 1,000 entries a Completed column of 700 cards is unusable; drag is weak on touch and needs a full keyboard alternative anyway; status is now one tap from every card and row (⋯ menu or status chip); it saves a dependency. Parity "Board/Table/Cards" becomes Grid (cards) / Table, with tabs doing the board's grouping. Open question 1.
- **Views**: Grid and Table on desktop; on phones Table becomes "List" rows (cover, title, status, progress, +1, edit). The choice lives in the URL (`?view=`).
- **Tabs are links**, server-rendered, URL slug ↔ enum: `all` (no filter), `watching` WATCHING, `planning` PLAN_TO_WATCH, `completed` COMPLETED, `on-hold` ON_HOLD, `dropped` DROPPED, `rewatch` REWATCH; Favourites is a separate `favourite=1` param (not a status), so it can later combine with a status. Links use `aria-current="page"`; not an ARIA tablist (the panel is the same list, filtered). Default tab: All, sorted by recently updated (parity).
- **Search** is server-side over English, romaji and native titles, debounced 250 ms, inside the current tab; while searching, tab counts show matches per status so a hit in another tab is visible. Sort options (parity): recently updated, title A–Z / Z–A, score high–low / low–high; table headers Title, Score, Updated set the same sort.
- **1,000 entries**: `GET /me/list?status&q&sort&cursor` paginated, page size 60 (max 100), cursor based; counts and totals from one summary call (`GET /me/list/summary`) so tabs are right without loading everything. First page server-rendered; next pages load on scroll (IntersectionObserver) with a "Next 60" link as fallback (`?cursor=`, works without JS). The cursor is the last row's (sort key, entry id), so ties and paging are stable; null scores sort last in both score orders. No virtualisation library: CSS `content-visibility: auto` on cards/rows (and one `<tbody>` per page) keeps 1,000 loaded entries cheap (left out of the mockup CSS because full-page screenshots would show skipped entries as blank); revisit only if a mid-range phone recording says otherwise. Sorting and the display rule run in the API, so pages never reshuffle client-side.
- **Display rule** (watched ≥ total shows Completed, except Rewatch) is computed in the API as the entry's displayed status, so counts, tabs, search and sort agree (Oshi no Ko and Solo Leveling in the mockups).
- **+1 rule**: the quick +1 (card, phone row, header) shows only for Watching, Rewatch and On hold, while progress is below a known total. The stepper in the table and the edit popover/sheet works for every status. Any +1 from Plan to watch or On hold also moves the entry to Watching (awards `list.mark_watching`); on Dropped it only corrects progress; on Completed + is disabled at the total and − lowers progress without changing the stored status.
- **Final +1**: when progress reaches a known total, the API stores COMPLETED (not just displays it) and awards `list.mark_completed`; that response is the finishing moment (chip + toast). Finishing a Rewatch adds one to rewatches and returns to Completed; `list.mark_completed` is deduped per anime, so it is not re-awarded. "Mark all N watched" is the same transition. The display rule above remains for rows stored earlier or imported.
- **Unknown episode totals** show "47 / ?", no progress bar, +1 never disabled. Known totals clamp: + is disabled at the total, − at 0.
- **Add control, header**: one split button. Main part adds as Plan to watch; chevron adds with another status; heart adds as Plan to watch + favourite. In the list it becomes "Status · 27 / 28 ▾" + "+1 ep" + heart; the status button opens the edit popover (status, episodes with "Mark all watched", score 1–10 with Clear, favourite, rewatch count for Completed/Rewatch, Remove). Autosave on every change, footer says Saved / Saving… / Not saved.
- **Add control, card**: the browse card's + opens a quick menu (radio statuses, "Edit episodes, score…", Remove when in list); once in the list the + shows the status dot. On phones the popover is a bottom sheet.
- **XP moment**: shown only when the server's response carries points (keys from PARITY: `list.add`, `list.mark_watching`, `list.mark_completed`, `list.mark_dropped`, `list.rate`). Small gold chip for every award; the toast with the level bar only for Completed. Never for a plain +1, never "0 XP" (cap or cooldown), merged within 2 s. Point values in the mockups (+40) are placeholders; the server owns them.
- **Remove** (new, the old site had none): in the popover, the card menu and the row ⋯ menu. No confirm dialog; an Undo toast for 8 s restores status, progress, score, favourite and rewatches. Does not refund XP (open question 2).
- **Errors are visible**: load failure = error state with Retry and error code; failed write = optimistic value rolled back with an inline message and Retry next to the entry (card, row, popover); next page failure = inline error, loaded entries stay; 401 on a write = sign-in prompt, change replayed once after sign-in.
- **Guest**: `/my-list` redirects to `/auth?mode=sign-in&next=/my-list` (auth design OTA-155 replaces the old RequireAuth wall); the add control, heart and card + open the auth sign-in prompt and keep the pending add.
- **MAL import (ships with OTA-143, post-launch, not OTA-142)**: the mockups show the entry points ("Import from MAL" in the page header and the empty state) and the `.xml` dialog (5 MB limit, imports earn no XP). The import itself is a background job (PARITY §7 and §8 feature table: the old single-request import was slow and unbounded) and shares its component with /settings/import-export. OTA-142 builds the page without these entry points.
- **Adult content (note only, no UI)**: entries with AniList `isAdult` / genre Hentai are filtered by the API unless the account is 18+ with "allow adult content"; counts, search and pages already exclude them.
- **Empty list**: onboarding panel (three steps, Browse + Import) plus a "Popular right now" row with quick-add cards; tabs, search and sort are hidden until the first entry.
- Liberties: header totals (anime, episodes watched, favourites) from the summary call; per-status colour dots; "Mark all N watched" shortcut; rewatch count shown as "Rewatch ×2".

## Worst-case content (break-ui)
Tested: 120-character romaji title, full-width + Japanese title, single-letter "K", 1,284 episodes with no total, 1,122 / ?, rewatch ×14, score 1 and 10, missing score, favourite + score + progress on one meta line, failed save on a row. Fixes applied in the mockups: titles clamp to 2 lines with `overflow-wrap: anywhere` and a reserved 2-line height so card rows align; numbers never truncate (tabular mono); card hover actions sit in a cover-sized overlay so they never cover the meta line; tabs `nowrap` (no "PLAN TO / WATCH" wrap on phones); the 7-column table becomes list rows below 768 px. Phone rows leave out the favourite heart (it shows in the Favourites tab, on cards and in the edit sheet) so the meta line never wraps. Card layout: info bottom-left (status chip, same corner as on browse cards), actions on top (+1 ep top-left, ⋯ top-right); a failed save replaces the meta line with the error and Retry. Titles use `word-break: normal` with `overflow-wrap: break-word` as the fallback. The 390 px shots use touch emulation (actions always visible).

## Accessibility check
- Contrast (computed, sRGB approximation of the oklab mixes): status tones on their 12% tinted fill 5.4–8.5:1 dark, 4.9–6.1:1 light; chips on cover art use a solid dark backing (≥ 4.6:1 even on white art); muted text about 7.1:1 dark / 6.7:1 light on the ground; zero-count tab numbers use `--muted` instead of `--faint` (under 4.5:1); ink on XP gold 11.9:1; error text on the error row 6.2:1. The build adds the `--ls-*` tones to `tokens.css` and `CHIP_TOKENS` in `tokens.test.ts`.
- Focus: every control has a 2 px `--accent-ink` outline with offset (`--accent` is about 1.65:1 on the light ground); card focus ring moves to the cover. Follow-up for the build: `components.css:53` (`.ol-btn:focus-visible`) and the browse `.br-add` ring still use `--accent`, the same issue system-wide.
- Targets: 44 px on phones (tabs, search and its clear button, sort, view toggle, +1, ⋯, sheet options, score buttons, Remove); desktop table steppers are 32 px (pointer: fine).
- Not by colour alone: every status chip, dot and tab carries its label; favourite is an icon with "Favourite" text for screen readers and `aria-pressed`; errors have text and an icon.
- Semantics: native `<table>` with `aria-sort`; steppers are groups with labelled buttons; status and score pickers are radio groups; save state and XP toast are `role="status"`, errors `role="alert"`; the XP chip is `aria-hidden`.
- Reduced motion: stated in `motion.md` (fades only, level bar jumps).

## Build notes for OTA-142
- API (new module or extension): `GET /me/list` (cursor, `limit` ≤ 100, `status`, `q`, `sort`), `GET /me/list/summary` (counts per displayed status + favourites + totals, same `q`), `PATCH /me/list/:animeId` (partial: status, progress, score 1–10 or null, favourite, rewatches; validated and clamped server-side, applies the +1 and final +1 rules, returns the entry and any XP award), `DELETE /me/list/:animeId`, and `PUT /me/list/:animeId` with the removed entry's values for Undo (8 s window). `:animeId` is our internal anime id (`AnimeDetails.id` from `GET /anime/:idSource/:externalId` and the slug payload), not the slug or an AniList id. XP is deduped per anime + action key on the server, so Undo or remove/re-add never re-awards `list.add`. Current user from the token. Error envelope codes (e.g. `LIST_UNAVAILABLE`, `LIST_ENTRY_NOT_FOUND`).
- Web: page is a server component reading search params; client islands only for the add control (Base UI Popover/Dialog/Menu), steppers and favourite (optimistic, `ApiResult` errors rendered inline), search input (debounced URL update) and the infinite loader. All calls through `apiClient()`.
- Add Sonner (toasts) and Motion in the first PR that needs them, with license and gzipped size (ADR 0012). No dnd-kit.
- MAL import entry points and dialog: OTA-143, not this build.
- Component tests: loading, empty list, empty tab, no results, load error, page error, failed write rollback, long titles, unknown total, display rule, guest redirect.
