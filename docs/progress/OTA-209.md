# OTA-209: pin anime image URLs (handoff)
Updated: 2026-11-23 (autopilot)

- API: `httpUrl` needs a literal `scheme://` (rejects `https:/x`, `https:host`). Images go through `imageUrlOn`: lowercase `https://`, ≤ 2,048 chars, no credentials or port, canonical (`new URL(u).href === u`), host `anilist.co` / `myanimelist.net` or a subdomain. `anilistImageUrl`, `myanimelistImageUrl`, exhaustive `sourceImageUrl`.
- Checked on import (AniList cover, banner, relation covers; Jikan covers) and again on read (`anime.rows`, `relation.rows` node and targets, `franchise.service` `currentFromCore`), so old rows are cleaned without a refresh.
- Web: `imageSrc` (`src/anime/image-src.ts`) checks form only (canonical `https://`, no port or credentials) for cards, header cover and banner, trailer poster, `og:image`. Hosts stay pinned by the API.
- Fallback: a rejected AniList cover lets `mergeAnime` take the Jikan cover; with none, the placeholder. A rejected banner shows the dot grid.
- `config.test.ts` pins `images: { unoptimized: true }`.
- Reviews ran on Opus (Fable limit reached until 2026-11-29): no Critical; all warnings fixed. A Fable security review is still owed, so the PR stays a draft.
- Integration tests not run in the cloud: Prisma's schema engine download is blocked by the proxy (`binaries.prisma.sh` 403). CI runs them.
