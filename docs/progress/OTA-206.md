# OTA-206: sign-out form says "reload" after a failure

Branch `fix/OTA-206-sign-out-reload-hint`. Spec: ADR 0015 Addendum (1f-iv-c2), amended in place. Web only, copy-only fix: no API change, no new state, variable, dependency or error code.
- `src/auth/sign-out-form.tsx`: `ALERT_TEXT` maps the state to the alert. `failed` reads "Could not sign out. Reload the page and try again."; `refused` keeps "Could not sign out" (a reload does not help there). Boundary, focus, placement and hide-while-pending unchanged.
- Tests: stale action id (Next's message) and offline rejections give the reload text, exactly one alert right after the button; failed then refused, refused then failed; a pending submit after a failure hides the alert; nothing reported from the browser (no `fetch`, `sendBeacon` or Sentry call).
- Decisions: a page loaded before a deploy posts a stale action id and lands in `failed` until a reload; the text now says so, and Sign out works after the reload (the cookie is untouched). Rejected: a `stale` state via `unstable_isUnrecognizedActionError`, an automatic reload (loops offline), Vercel Skew Protection (project on Hobby, availability unconfirmed; offline still needs the text). Known limits: a thrown action also gets the reload advice; offline, a reload shows the browser's offline page.
- Documented, not coded: a submit before hydration is a full-page POST answered with a plain-text 409 "Server Action unavailable." (read in Next 16.4.5, not run). Farouk decides: the real fix is a stable-URL sign-out route handler (a `secure-builder` ticket).
- Not verified by running: a browser across two builds (stale id after a deploy, then reload and sign out).
- Next: Farouk's call on the stable-URL route handler; the browser check above on beta after the next deploy.
