# OTA-224: per-IPv6 /48 limit for sign-up and resend

- Changed: `PER_IPV6_SITE_LIMITS` gains `sign-up` and `email-verification-resend`, 30 per /48 per hour each, counted after the /64 (a refused /64 never spends the /48). API only; no schema, variable, dependency or error code. Swagger strings, ADR 0020 Addendum (OTA-224), `.claude/rules/api.md`.
- Why 30: 6x sign-up's /64 limit (5/h), 3x resend's (10/h); per /48 up to 30 hashes and 60 mails per window (59 and 118 across a window boundary, ADR 0015 trade-off).
- Tests: rules spec (table pin, order, no /48 for IPv4 or mapped IPv4, distinct keys per route, respelt key throws); sign-up and resend integration (a /48 full at exactly 30, a refused /64 not counted at the /48, other /48 and IPv4 still 202, no extra hash or mail).
- Environment caveats (cloud run): Node 22, Postgres 16 (not 18), migrations applied with psql through a test-only pnpm shim (Prisma schema engine download blocked), real argon2 not run (fake in these specs).
- Open: sign-in /48 tier (Gate, hard blocker with the global mail cap before `canSend()` is true in production); the existing ADR 0020 budget-before-token question is filed separately.
