# OTA-201: health check refuses a non-UTC session

- `HealthService.check` runs `SELECT current_setting('TimeZone') AS zone` in the same 2 s race as before.
- Pure `sessionZoneOf(rows)` reads the first row's `zone`; `REQUIRED_SESSION_ZONE = 'UTC'`, strict equality (`Etc/UTC` and `utc` fail).
- Non-UTC or unreadable answers the existing 503 `{ status: 'error', checks: { database: 'down' } }` with one warning (zone capped at 64 chars, rows never logged).
- Reason: poolers can drop the startup `options` that OTA-200 relies on, so the pin would fail without a sign.
- Unit tests: UTC, three wrong zones, four malformed answers, long zone, existing failure and timeout cases.
- Integration: 200 on the normal app; 503 with `no-store` on a client built without `databasePoolConfig` and `-c timezone=Asia/Tokyo`.
- Docs: `.claude/rules/api.md`, `docs/architecture.md`, `README.md`, ADR 0002.
- Not run in the cloud: API tests and typecheck need Prisma engines; CI runs them.
