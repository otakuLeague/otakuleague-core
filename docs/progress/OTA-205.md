# OTA-205 slice 205-a: sign out everywhere (API)

Branch `fix/OTA-205-unconfirmed-sign-out`. Spec: ADR 0015 Addendum (OTA-205), decisions 1-3 and 9. API only, additive: no caller yet, no migration, no new variable, dependency or error code.
- `SessionService`: one private data-modifying CTE, `UPDATE app_user SET session_epoch = session_epoch + 1, updated_at = <Clock>` then `DELETE FROM auth_session WHERE user_id IN (SELECT id FROM raised)`. The DELETE depends on the UPDATE's output, so the user row is locked first, then the sessions (the cleanup's order), and nothing is deleted when the UPDATE matched no row. `signOutEverywhere(userId, expectedEpoch)` adds `AND session_epoch = expectedEpoch`; `revokeAll(userId, tx)` is unconditional for OTA-140 (transaction client required, READ COMMITTED only). Logs nothing; database errors propagate (503).
- `SignedInSession.sessionEpoch`: the user epoch `resolve` already reads. `GET /me` does not send it.
- `POST /auth/sign-out-everywhere` in `AuthController`: `SessionGuard`, `@CurrentSession()`, 204, Swagger like sign-out. The member and epoch come from the session row only; body and query are ignored.
- `sign-out-everywhere.integration.spec.ts` (22 tests): 204 with no body, epoch +1, `updatedAt` = clock, all of the member's rows gone (expired and old-epoch ones too), another member untouched, no warning and no secret in any log level; next `GET /me` 401 for both tokens, 200 for the other member; a row written afterwards with the old epoch is 401, the new epoch 200; replay 401 with the epoch raised once; missing, malformed, other-scheme and unknown tokens 401; expired, past the hard stop, earlier-revoked and unverified sessions 401 with nothing changed; preview, wrong and missing key 403 `INTERNAL_KEY_REQUIRED`; open caller 403; statement failure 503 and the member stays signed in; two sessions, and one token twice, both past the guard (forced by a held row lock): both 204, epoch +1 exactly, 0 rows; `revokeAll` in a transaction: rollback changes nothing, commit raises once and deletes every row.
Decisions: no unit spec (the repo has none for `AuthController` or `SessionService`; the SQL needs Postgres). A call that resolved an epoch already raised is 204: every session of that epoch is ended. The epoch rises at most once per sign-in (a raise needs a session holding the current epoch), so `int4` overflow is out of reach.
Review fixes (code and security reviews, no Critical): conditional epoch, `revokeAll` with a required `tx`, forced races, the transaction cases; ADR addendum amended: 205-c answers `session_ended` on a 401 or no cookie (only a 204 is success); 205-b ships after OTA-207 with at most 20 retries in flight per instance; 429 handling (no API limiter on sign-out today, validated `retryAfterSeconds` only, a platform 429 is a fault); `maxDuration` and `connection()` inside `after()` to check in 205-b.
Checks: lint, typecheck, API unit tests green; integration specs sign-out-everywhere, me, sign-in, session-time-zone green on local Postgres 16 (migrations applied with psql: the Prisma schema engine could not be downloaded in the cloud run). A mutation (route made unconditional) fails both forced-race tests.
