# OTA-205 slice 205-a: sign out everywhere (API)

Branch `fix/OTA-205-unconfirmed-sign-out`. Spec: ADR 0015 Addendum (OTA-205), decisions 1-3 and 9. API only, additive: no caller yet, no migration, no new variable, dependency or error code.
- `SessionService.revokeAll(userId, db = this.prisma)`: one data-modifying CTE, `UPDATE app_user SET session_epoch = session_epoch + 1, updated_at = <Clock>` then `DELETE FROM auth_session WHERE user_id IN (SELECT id FROM raised)`. The DELETE depends on the UPDATE's output, so the user row is locked first, then the sessions (the cleanup's order). Takes a transaction client for OTA-140. Logs nothing; database errors propagate (503).
- `POST /auth/sign-out-everywhere` in `AuthController`: `SessionGuard`, `@CurrentSession()`, 204, Swagger like sign-out. The member comes from the session row only; body and query are ignored.
- `sign-out-everywhere.integration.spec.ts` (18 tests): 204 with no body, epoch +1, `updatedAt` = clock, all of the member's rows gone, another member untouched, nothing secret logged; next `GET /me` 401 for both tokens, 200 for the other member; a row written afterwards with the old epoch is 401, the new epoch 200; replay 401 with the epoch raised once; missing, malformed, other-scheme and unknown tokens 401; expired, past the hard stop, earlier-revoked and unverified sessions 401 with nothing changed; preview, wrong and missing key 403 `INTERNAL_KEY_REQUIRED`; open caller 403; statement failure 503 and the member stays signed in; two parallel calls (5 rounds) each 204 or 401, at least one 204, 0 rows, epoch = initial + number of 204s.
Decisions: no unit spec (the repo has none for `AuthController` or `SessionService`; the SQL needs Postgres). A call whose session was valid at the guard but deleted by a parallel call still answers 204: the statement ran and every session is gone. `session_epoch` is `int4`: overflow would need about 2^31 sign-ins, each rate-limited.
Checks: lint, typecheck, API unit tests (1,138) green; integration specs sign-out-everywhere, me, sign-in, session-time-zone green on local Postgres 16 (migrations applied with psql, because the Prisma schema engine could not be downloaded in the cloud run). Not yet: code and security review (`/ship`).
