# OTA-200: Postgres session time zone pinned to UTC

- `@prisma/adapter-pg` drops the offset on `timestamptz` reads and writes, so a non-UTC session zone shifted session expiry.
- `databasePoolConfig()` (`apps/api/src/prisma/database-pool.ts`) adds `options: '-c timezone=UTC'`; `PrismaService` and `connectTestDatabase` use it.
- `DATABASE_URL` with an `options=` parameter is refused at boot (env validation) and by the helper (pg lets the URL win).
- Integration spec on an `Asia/Tokyo` clone: zone check, Postgres-computed epochs, `resolve` on sessions seeded with explicit offsets.
- Not pinned: `connectMaintenance`, `prisma migrate`, psql. Migration SQL writes timestamp literals with an explicit offset.
- Before merge: run `SHOW timezone` on Railway's Postgres. If it was ever not UTC, stored rows are shifted.
- Follow-up: OTA-201 (health check answers 503 when the zone is not UTC, for poolers that drop the option).
