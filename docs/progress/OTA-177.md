# OTA-177: Seasonal and genre lists, slice 2 (autopilot, 2026-11-13)

Plan: ADR 0016, "Addendum: slice 2". API and shared-types only; no migration, no web.

## Shipped

- `GET /anime/lists/seasonal` with `season` + `year` (both or neither; neither is the current UTC season), and `genre` on every kind. Max page size stays 50, same cursor.
- `AnimeListPage.season` is `{ season, year }` for `seasonal`, null otherwise. `ANIME_GENRES`, `ANIME_LIST_MIN_YEAR` and `AnimeListSeason` are in shared-types.
- `resolveCatalogList` (pure, `anime-list.query.ts`) owns the cross-field and clock rules and returns a discriminated result; the service turns `invalid` into 400 `VALIDATION_FAILED` right after the cursor check, before the kill switch. `listKey(list)` and `listQuery(list)` are built from the resolved `CatalogList`.
- `ANILIST_LIST_QUERY` takes `$season`, `$seasonYear`, `$genre`; unset keys are not sent.
- Fixture `lists/anilist-seasonal-fall-2026.json` is synthetic (listed in the fixtures README).

## Decisions

- `listSpec` was removed: the service only needs the query (`listQuery`) and the lifetime (`isFresh`), and nothing else read it.
- The violations of the one failing rule are all reported in `details` (a season and a year on `top` name both fields); a season without a year and a bad year are separate rules.
- Review fixes: global cold-fetch bucket `ListFetchLimits` (6 tokens, one back per 10 s; 429 `LIST_FETCH_LIMITED`; background refreshes share it); `year` only from 4 plain digits; `CatalogList` is a union; quiet logs for queue full and cooling down.

## Not run in the cloud session

Prisma client and engines are unavailable here, so API typecheck, lint on files that import Prisma types, the OpenAPI spec and the integration spec ran only in CI. Unit specs without Prisma pass.
