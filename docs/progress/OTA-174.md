# OTA-174: cap source body size and synopsis length, linear tag strip

- Source HTTP client reads bodies through `readCappedBody` with a 1 MiB decoded limit (Content-Length precheck, then a streamed byte count). An oversized or unreadable body throws `UnusableAnswerError` and does not trigger the source cool-down.
- Import service backs off per id. The franchise walker halves an oversized batch (`fetchSplitting`) and backs off a single id that still overflows.
- `synopsisText` cuts raw input to 20,000 chars first, then trims a lone surrogate, an unfinished tag, or an unfinished entity.
- New linear `stripTags` replaces the quadratic regexes. Entity lookup is guarded with `Object.hasOwn`.
- Body read errors now report as network failures, not "not JSON".
- Decisions: no cool-down for oversized answers (one id cannot take a source down). The 20,000 number matches the web cap by comment, not a shared constant.
- Known: a literal `<!-- -->` in a synopsis is kept as text. Synopses already stored above 20,000 chars stay until refreshed.
- Not run in cloud: franchise-walker.spec.ts, integration, full lint/typecheck (Prisma engines blocked). CI is the check.
