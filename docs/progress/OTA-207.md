# OTA-207: throttle for Server Action POSTs

Spec: ADR 0015 Addendum (OTA-207). Web only: no API change, no new variable, dependency or error code.
- 207-a (#135, merged): `clientNetworkOf` (`api/client-ip.ts`); `createActionThrottleKeyer` (HMAC-SHA256) and `createActionThrottle` (fixed window, 60 per 60 s, 10,000 entries) in `auth/action-throttle.ts`.
- 207-b (#145, merged): `isPossibleActionPost`/`isCrossSitePost` (`auth/action-post.ts`, parity test with Next); `auth/action-throttle-guard.ts` in `proxy.ts`: cross-site 403 uncounted, /64 at 60 and /48 at 300 per 60 s, 429 `text/plain` `ACTION_THROTTLED_TEXT` with `Retry-After`; unknown IP passes uncounted with a tags-only report.
- 207-c (this branch): `SignOutFormState` gains `throttled`, set only by the form's boundary via `signOutStateFromThrow` (an `Error` whose message is exactly `ACTION_THROTTLED_TEXT`). The boundary's state type excludes `refused`. A pin test reads Next's `server-action-reducer.js` (the text/plain body becomes the error message); if it fails after an upgrade, re-check `signOutStateFromThrow`.
- Decisions: copy "Could not sign out: too many requests from your network. Wait a minute, then try again." (true behind a shared NAT, the 429 body's words, no "go back" in a menu). ADR F16 amended to it, pending Farouk's confirmation (decision 7).
- Checks: lint, typecheck, web unit tests green (1390 tests in 83 files).
- Not verified: `next build`, Vercel `has` matchers, Sentry in the proxy function on Vercel.
