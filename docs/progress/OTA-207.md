# OTA-207 slice 207-a: action throttle core

Branch `feat/OTA-207-server-action-throttle`. Spec: ADR 0015 Addendum (OTA-207). Web only (one comment line in the API): no API change, no new variable, dependency or error code. Nothing imports the new code yet.
- `apps/web/src/api/client-ip.ts`: `clientNetworkOf(clientIp)` (IPv4 as is, IPv4-mapped IPv6 to its IPv4, other IPv6 to its /64), same rule as the API's `visitorKeyFromClientIp`; each names the other, both specs run the same address table. It stays in `client-ip.ts` (imports `next/headers`): whether `next build` accepts that in the proxy's graph is unverified; if not, 207-b moves the pure functions to a file without that import.
- `apps/web/src/auth/action-throttle.ts`: `createActionThrottleKeyer(secret)` (HMAC-SHA256, base64url, secret of 32 bytes or more held as a `KeyObject`, takes a branded `ClientNetwork`) and `createActionThrottle(config, nowMs)` with `take(key)` (`allowed` | `limited { retryAfterSeconds }`, 1 to 60), `forgetEnded()` and `size()`; it throws on a config that is not positive safe integers. Fixed window; a refused POST neither counts nor extends it; the oldest entry goes at `maxEntries`. Defaults exported as constants (60, 60,000 ms, 10,000) and pinned by a test.
Checks: web tests for both files, API `api-caller.spec.ts`, lint and typecheck green.
Edge cases covered by tests: empty throttle, a single POST, 59/60/61, window end at -1 ms/+0, Retry-After 1 at 1 ms left, clock step back, eviction order, bad config, short secret. By design, not tests: no IP means 207-b passes uncounted; the store is memory, so a deploy resets every count; rotating IPs are OTA-197.
