# OTA-184: Browser data ADR, slice 1 (autopilot, 2026-11-13)

Plan: architect, slice 1 of 2. Docs only: no dependency, no code, no protected path.

## Decided (ADR 0017)
- TanStack Query 5.107.1 (MIT, 10.8 kB gzipped measured with esbuild, React external) for browser data; Server Components stay the default, Server Actions stay for forms that navigate.
- Browser → same-origin route handler (`app/api/<area>/…/route.ts`) → `apiClient()` → API. No CORS; the `HttpOnly` cookie never leaves the web origin (ADR 0015). Rejected: CORS, Server Actions as transport (queued one at a time, break on deploy), a catch-all proxy.
- `client.ts` stays the only `fetch` site: the browser reuses `createApiClient` on `<origin>/api`. No ESLint change for the network rule.
- `ApiResult` at the network boundary; inside a hook only, a failure becomes a thrown `ApiFailureError`, so TanStack keeps good data, retries and rolls back.
- One file and one hook per call, `getQueryKey` on the query hook, invalidation awaited inside the mutation hook, `staleTime` per data kind, retry on 5xx except 504, optimistic +1 with rollback.
- ADR 0003 status line points here; `.claude/rules/web.md` has the rule and the checklist line.
