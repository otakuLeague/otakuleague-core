# OTA-184: Browser data ADR, slice 1 (autopilot, 2026-11-13)

Plan: architect, slice 1 of 2, then one code-review pass applied. Docs only: no dependency, no code, no protected path.

## Decided (ADR 0017, proposed; accepted when slice 2 merges)
- TanStack Query 5.107.1 (MIT, 10.8 kB gzipped measured with esbuild, React external) for browser data; Server Components stay the default, Server Actions stay for forms that navigate.
- Browser → same-origin route handler (`app/api/<area>/…/route.ts`, one per call) → `apiClient()` → API. No CORS; the `HttpOnly` cookie never leaves the web origin (ADR 0015). Rejected: CORS, Server Actions as transport, a catch-all proxy.
- `client.ts` stays the only `fetch` site and keeps the isomorphic `createApiClient`; `apiClient()` and the session, client IP and key options move to a `server-only` file.
- `ApiResult` at the network boundary; inside a hook only, a failure becomes a thrown `ApiFailureError`; components read it through an `instanceof` helper. The browser cache is cleared on sign-in, sign-out and any 401 from a member route (keys carry no viewer).
- One file and one hook per call, `getQueryKey` on the query hook, invalidation awaited in the mutation hook, `staleTime` per data kind, retry only on 500 and 503, optimistic +1 with rollback.
- Pointers added: ADR 0003 status line, ADR 0015 CSRF row, `.claude/rules/web.md` (rule and checklist line).
