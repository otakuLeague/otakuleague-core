# OTA-138: authentication ADR (autopilot, 2026-11-12)

- ADR 0015 (`docs/decisions/0015-authentication.md`): own opaque sessions in a NestJS `auth` module on Postgres (hashed tokens, 30 d idle / 180 d max), no auth library, no JWT. Better Auth is the recorded fallback, with a dated switch-or-cut trigger.
- Cookie `__Host-ol_session` is host-only on the web origin; the web server forwards it to the API as Bearer plus `X-Internal-Api-Key`. No shared cross-subdomain cookie, no CORS. CSRF: Server Actions + Origin check; the three state-changing GETs (verify, reset link, Google callback) are listed with their own guards.
- argon2id via `node:crypto` (needs Node ≥ 24.7), rate limits and email budget in Postgres (HMAC-hashed keys), Brevo for email (300/day free, EU) behind `EmailSender`.
- Charter deviations (§8 provider, §9 JWT, action-verb routes) listed in the ADR; pointer in `docs/engineering-charter.md`.
- Reviews: code-reviewer and security-reviewer, no Critical; all Warnings folded into the ADR.
- Runtime proof (sign-up → cookie → `GET /me`) moved to OTA-139's first acceptance criterion: cloud runs can't run it (Node 22, Prisma engines blocked).
