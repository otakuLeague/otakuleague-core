# OTA-222: sign-in password emptied when hidden

- `clearOnHide` moved to `apps/web/src/auth/clear-on-hide.ts`; both password inputs (sign-in, sign-up) use it, so leaving `/auth` (route hidden in `<Activity>`) empties them. Dev StrictMode re-attaches the ref, so a pre-hydration password is kept in production only.
- Security review found the "Create one" switch is search-params only: the route stays visible and sign-in is hidden by CSS, so no ref cleanup runs. Fix: `SignUpForm` empties `#sign-in-password` (`SIGN_IN_PASSWORD_ID`) on mount, never reading it. Mutation-checked: removing the effect fails exactly the two new tests.
- Reviews: code-reviewer twice, security-reviewer (Fable): no Critical. Open Minors: the switch effect lives in `SignUpForm` (a second use elsewhere would also wipe a sign-in password; could move to `SignUpPanel`); a password manager could autofill the CSS-hidden sign-in password on a hard load of `/auth?mode=sign-up`; the sign-in identifier survives a hide by design (same as the sign-up Minor).
- Not browser-verified: type, "Create one", back, forward on `next start` (Firefox too).
