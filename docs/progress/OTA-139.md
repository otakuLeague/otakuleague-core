# OTA-139 slice 1f-iii-c: redirect ban, dynamic import gate, shared credential limits

Branch `feat/OTA-139-redirect-ban`. Lint and constants only; no runtime behaviour change.
- `no-restricted-syntax` (`apps/web/eslint.config.mjs`): `redirect`/`permanentRedirect` from `next/navigation` (named, aliased, string-named, `default`, namespace, default import, re-exports, `next/navigation.js`) and anything from `next/dist/` banned app-wide except `src/auth/redirect-to.ts`, `src/anime/resolve-tab.ts`, `src/anime/season-redirect.ts`.
- L3 gate, everywhere including those three: `import()` must take a string literal and never `next/navigation`, `next/dist/` or `…api/client` (`import('./client')` inside `src/api` stays allowed). `require()` stays `@typescript-eslint/no-require-imports` (pinned by a row).
- `IDENTIFIER_MAX` (254) and `PASSWORD_RAW_MAX` (1024) now live in `packages/shared-types/src/auth.ts`, used by the API DTOs and the web sign-in form; the web's `SIGN_IN_*` copies are gone. Values unchanged.
- Tests: redirect and dynamic-import rows in `network-lint-rule.test.ts`; shared-types pins `[254, 1024]`; API pins `PASSWORD_RAW_MAX = 8 × PASSWORD_MAX`.

Decisions: also banned `default` and string-named imports and `next/navigation.js` (next has no exports map, so each reaches the same `redirect()`); the anime helpers stay allowlisted (targets from `tabHref()` on an API-validated canonical slug). ADR 0015 Addendum (1f-iii-c), pointer in ADR 0003.
Deferred: `NextResponse.redirect`/`Response.redirect` are not covered (matters at 1f-vi, the first auth route handler); an `apiClient` aliased or wrapped after a legal import is not lintable.
Next run: 1f-iv `Viewer`/`loadViewer`/`signOutAction`/`sessionCall`; its signed-out redirect must be a second helper inside `redirect-to.ts`, never a fourth allowlisted file.
