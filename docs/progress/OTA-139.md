# OTA-139 slice 1e-ii-a: email confirmation route

- `POST /auth/email-verification/confirm` (`email-verification.{controller,service,dto}.ts`), `AUTH_TOKEN_INVALID`, shared `EmailVerificationConfirmRequest`/`Response` and `isEmailVerificationConfirmResponse`.
- Pre-hijack gate closed (ADR 0020 Addendum 1e-ii): without a matching binding, confirming needs the sign-up password; wrong is 401 `INVALID_CREDENTIALS`, nothing consumed. Only the binding path returns a session.
- Limits: 10 per IP per 15 min; 10 password tries per account per hour (counted only before a hash).
- Transaction re-checks everything inside its WHERE clauses (user locked first; token still live and bound; hash still the one the password matched). Races with re-submit and cleanup tested deterministically.
- Split decided by `architect`: resend is slice 1e-ii-b (next). Resend no longer moves the account deadline (Addendum).
- Gate additions for production sign-up: UNIQUE(`user_id`, `purpose`) on `auth_token` (with 1e-ii-b), a 24 h per-email cap on unbound password guesses.
- Cloud runs can now run API lint/typecheck/unit: `PRISMA_SCHEMA_ENGINE_BINARY=/bin/true PRISMA_ENGINES_CHECKSUM_IGNORE_MISSING=1 pnpm exec prisma generate`. A throwaway local Postgres 16 (apt) ran the integration spec.
- Next: 1e-ii-b resend (+ the UNIQUE migration), then 1e-iii availability + common-password list, then 1f web.
