# OTA-139 slice 1f-iv-b2: sign-in fault reports and unconfirmed sign-out revocation

Branch `feat/OTA-139-auth-fault-reports`. Server code only, no UI. Spec: ADR 0015 Addendum (1f-iv-b2).
- Reporter renamed `apps/web/src/auth/report-credential-refusal.ts` → `auth-reports.ts`; `AuthReportKind = AuthCallFault | 'revocation_unconfirmed'`, one throttle slot per kind (6/h per warm instance).
- Sentry tag `credential_route` → `auth_route`: the redaction scrubber masked any key matching `credential`; a test now pipes every reporter output through `scrubErrorEvent`.
- Sign-in Server Action reports `internal_key_refused` / `invalid_response` (< 500); timeouts, 429, 5xx, credential errors report nothing.
- `deleteSession`: only an empty 204 or a 401 `UNAUTHORIZED` is silent; any other failure sends exactly one report (the fault, else `revocation_unconfirmed`). Covers sign-out and the old-session delete inside sign-in.

Decisions: the Host-based loopback client-IP check (Addendum 1f-iv decision 6) is withdrawn: `isSameOrigin` already refuses every browser off `WEB_PUBLIC_URL`, a script can forge `Host`, and `isSecureApiBaseUrl`/`assertKeyMayGoTo` still guard key/Bearer/password. Size +245/−72.
Reviews (Fable): code no Critical (Importants fixed: sign-in delete reports asserted, scrubber test, ADR inline notes); security no Critical/High/Medium (L1 per-instance throttle: consider a Sentry inbound rate limit on fingerprint `auth-call-fault`; L2–L4 fixed). Open: report throttle is per kind across routes (a `/me` `invalid_response` can hide a sign-in one); `reportClientIpUnknown` has no try/catch.
Earlier follow-ups still open: L3 test that `'use server'` files export only one `*Action` (with 1f-vi walker); L5 API: preview Bearer → 403; L6 `isExpectedBody` overloads; `isMeResponse` vs imported usernames; `NextResponse.redirect` (1f-vi); `/sign-up` 308 (1f-v); frame-ancestors before signed-in pages; no `Referrer-Policy: no-referrer` on any page once the header holds the sign-out form (iv-c).
