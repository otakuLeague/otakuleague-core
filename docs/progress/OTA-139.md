# OTA-139 slice 1f-iv-b: sign-out action and old-session delete

Branch `feat/OTA-139-sign-out`. Server code only; `signOutAction` has no caller until iv-c (header button). Spec: ADR 0015 Addendum (1f-iv-b).
- `deleteSession(session)` (`apps/web/src/auth/delete-session.ts`, not a `'use server'` file): one `POST /auth/sign-out` via `sessionCall`, 2,000 ms, never retried, total. 204/401/timeout/5xx/429 resolve silently; faults (`internal_key_refused`, `invalid_response`) → `reportAuthCallFault('sign-out', …)`; throws → `unstable_rethrow`, then `configuration`.
- `signOutAction()` (`sign-out-action.ts`, no parameters): preview → return before `WEB_PUBLIC_URL`; refused `Origin` → return, 0 cookie reads/writes; token only from the cookie; clear with `cookies().set(name, '', clearedSessionCookie)` (never `delete()`, which drops `Secure`); `redirectToSignedOut()` (`/`, replace) in `redirect-to.ts`.
- Sign-in reads the old cookie after the form check and deletes that session only after a successful sign-in; a failed delete never fails the sign-in.

Decisions: iv-b split again: iv-b2 = loopback host check, sign-in fault reports, rename reporter to `auth-reports.ts`, `revocation_unconfirmed` report. A refused sign-out returns `void` for now; iv-c returns a `refused` state and shows "Could not sign out" (stripped Origin or changed `WEB_PUBLIC_URL`). Size +499/−11 (~375 tests + ADR).
Reviews (Fable): code no Critical (Important: action-level tests with the real `deleteSession`, ADR refusal wording, both fixed); security no Critical/High/Medium (L1 revocation unreported, L2 sign-in faults → iv-b2; L3 test that `'use server'` files export only one `*Action`; L5 unthrottled sign-out ≈ one `GET /me`, recorded).
Earlier follow-ups still open: L3 lint row for `sessionTokenFrom` as only brand maker; L5 API: preview Bearer → 403; L6 `isExpectedBody` overloads; L8 `credential_route` tag rename; `isMeResponse` vs imported usernames; `NextResponse.redirect` (1f-vi); `isAnimeSlugResolution`; `/sign-up` 308 (1f-v); frame-ancestors before signed-in pages; no `Referrer-Policy: no-referrer` on any page once the header holds the sign-out form (iv-c).
