# OTA-139: sign-up v3b-a (confirm, checklist, gate)

- Two PRs. PR A (`refactor/OTA-139-shared-password-rule`): the ADR 0015 "Addendum (v3b)" and the shared rule. PR B (`feat/OTA-139-sign-up-v3b`, merged after A): the web slice below.
- Shared rule: `PASSWORD_MIN`, `signUpPasswordRules` and `meetsSignUpPasswordRule` moved to shared types; the API's DTO imports them, behaviour unchanged (NFC first). The API's 11 cases run in `packages/shared-types/test/password-rules.test.mts`; two `SignUpDto` rows keep the NFC boundary pinned in the API.
- Web: "Confirm password" (no `name`, never posted), the `ul.au-rules` checklist instead of the hint line, and `signUpSubmitBlock` before the action (0 calls on an unmet rule or a mismatch, message under the field, `aria-invalid`, focus). Only two booleans and the block live in React state; both reset when the action answers and when `<Activity>` hides the form. Mutation-checked: dropping either reset fails a container test.
- Design deviations: the password is described by the two rule items, not the mockup's `aria-label`led list (its label would replace their text in the description); the rules message sits between the password and the checklist. No "(4 / 8)" counter (ADR).
- Next: v3b-b, Show buttons (`PasswordInput`, sign-in too) and `FocusHeading`.
