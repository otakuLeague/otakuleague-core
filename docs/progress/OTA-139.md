# OTA-139: email link handler (slice 1f-vi-a)

- Slices so far: #150 shared password rule, #151 v3b-a, #152 v3b-b, this PR 1f-vi-a (`feat/OTA-139-verify-link-1f-vi`): ADR 0015 "Addendum (1f-vi)", the GET handler with its pure core, cookies and gates. Web plus one shared constant: no API change, variable, dependency or error code.
- Shared types: `EMAIL_VERIFICATION_LINK` (`path` `/auth/verify`, `tokenParam` `token`); its test checks the redaction masks `token=` in text. `app/route-handlers.test.ts` holds `app/auth/verify/route.ts` to it.
- Cookies (`auth-cookies.ts`, through `authCookie`): `verifyCookie` (`ol_verify`, 600 s) and `clearedSignUpCookie` (`Max-Age=0`, `Secure` on https). Privacy table row renamed to `__Host-ol_verify` (`lastUpdated` unchanged: same cookie, its real name).
- Pure core `src/auth/email-link.ts`: `EMAIL_LINK_LANDINGS` (six relative constants) and `EmailLinkLanding`; `isLinkNavigation` (review: GET, Fetch Metadata absent or `navigate`/`document`, no `Sec-Purpose`, no `Purpose: prefetch`); `emailLinkTokenFrom` (exactly one `token`, 43 base64url, else nothing); `wellFormedAuthToken` (the token shape, used on the binding); `VerifyLinkOutcome` and `verifyLinkOutcomeFrom` (by `outcome` and code only: `AUTH_TOKEN_INVALID` is `expired`, any other failure or refusal `try_again`, `verified` with `session: null` is `confirmed`); `landingOf`.
- `src/auth/see-other.ts`: `seeOther(landing)`, bodiless 303 with `Location`, `Cache-Control: no-store` and the no-Referer policy; the referrer guard names it as its one exception and checks the literal appears exactly once.
- Handler `src/auth/verify-email-link.ts` + `app/auth/verify/route.ts` (GET only), in the addendum's order plus the navigation check after the preview (HEAD, a subresource, a frame or a prefetch → `try-again`, 0 reads, 0 calls); `'email-confirm'` joins `AuthCallRoute` and `ClientIpRoute`. `next.config.ts` `logging.incomingRequests.ignore` keeps `/auth/verify` (and its token) out of the dev request log.
- Gates: `no-restricted-syntax` bans `.redirect` on `NextResponse`/`Response` (dot, string or template key, one member deep such as a namespace or `globalThis`, top-level destructuring) and an aliased `NextResponse` value import, except in `src/anime/slug-proxy.ts`; `auth-cookie-importers.test.ts` pins the files naming each cookie helper and the files holding `ol_signup`/`ol_verify`/`ol_flash` (comments count); `route-handlers.test.ts` pins `hikari` POST and `auth/verify` GET.
- Tests: core table (every row of the addendum, 11 malformed-token cases, navigation rows), `seeOther` on each landing, handler (0 calls and 0 cookie reads on a preview, a bad token, HEAD, an image, a script fetch, an iframe, a prefetch, a prerender, a legacy `Purpose`; a mail click and a browser without Fetch Metadata pass; binding only when well-formed and under the configured name, a planted plain `ol_signup` ignored, revoke-then-set-then-clear order, `ol_verify` only on `confirmation_required`, no cookie on replay/`already_verified`/`session: null`/400/429/5xx/outage/refusal, reports only for faults and `client_ip_unknown`, a throw → `try-again` + `configuration`, a `request.url` getter throwing `NEXT_PRERENDER_INTERRUPTED` rejects with 0 reports, reads and calls, the token in no console line, report or scrubbed event), config row, lint rows, scans. Mutation-checked: removing `unstable_rethrow`, the navigation check, `deleteSession`, the binding check, the `ol_signup` clear, or writing `ol_verify` on every outcome each fails a test.
- Decisions: the handler pin lives next to the route and imports each pinned file with a literal `import()` (lint allows literals only). Read in Next 16.4.6: a sync `request.url` in a prerender throws `NEXT_PRERENDER_INTERRUPTED`, which `unstable_rethrow` passes; `cookies().set()` is merged into a returned `Response`; the dev log's `ignore` patterns are tested against the path with its query. Review fixes amended the addendum: the navigation check replaces the accepted prefetch/HEAD wrinkle (residual: a forced top-level navigation still counts), "a logged token is worth nothing alone" holds for a third party only (whoever created the pending sign-up holds binding and password), and `/auth/verify` has no web-tier throttle.
- Open Minors: a throw after the session cookie is set (only `jar.set` itself could) lands on `try-again` with the cookie kept; the 5,000 ms confirm timeout is the client's default, not stated in `credentialCall`; `sessionToken` in `VerifyLinkOutcome` is a plain string (a shape the guard checked, not a brand); the route pin walks `app/` only; no web-tier throttle on `/auth/verify` (the API's 10 per IP per 15 min bounds it; follow-up to file); `try-again` shows no wait time for a 429; lint blind spots: `Reflect.get`, a subclass, an aliased `Response` binding, assignment or nested destructuring, a hand-written `Location` on a 3xx.
- Not verified by running: `next build` with this GET handler under `cacheComponents`, the 303 and its cookies on `next start` and on Vercel's edge, a click from webmail and from a mail app sending the `SameSite=Lax` binding and the Fetch Metadata the gate expects, whether a browser keeps a prefetched `no-store` 303, what Vercel's request log keeps of the query (must be checked before any mail carries a link).
