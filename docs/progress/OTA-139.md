# OTA-139: accounts slice 1c-ii, sign-in and sign-out routes (2026-11-17)
## What changed
- `POST /auth/sign-in` and `POST /auth/sign-out` (`apps/api/src/auth/auth.controller.ts`, registered in `AuthModule`).
- `CredentialGuard` (`credential.guard.ts`) + `@ClientIp()`/`clientIpOf`: after `InternalKeyGuard`, before validation; `web` callers only (`open`/`preview` 403 `INTERNAL_KEY_REQUIRED`); a `web` caller without a valid `X-Client-Ip` (shared `unknown` key) 400 `BAD_REQUEST`. The IP lives in a WeakMap only the guard writes.
- `SignInDto` (`sign-in.dto.ts`): identifier non-empty and not blank, at most `IDENTIFIER_MAX`, no U+0000; password non-empty, at most `PASSWORD_RAW_MAX` (1024) UTF-16 units before NFC, then at most `PASSWORD_MAX` code points after NFC (custom validator, checks `typeof` first, never echoes the value). `passwordBytes` (hasher) also refuses over `4 * MAX_PASSWORD_BYTES` units before NFC (review M1: 1.7 s of NFC measured on a 96 KB crafted combining-mark string, before the limiter).
- `SignInService` (`sign-in.service.ts`): `signIn({ identifier, password, ip })` → `signed_in | invalid_credentials | rate_limited`. Normalise, `AuthRateLimiter.check(signInHits(...))` before the lookup and any hash, one unique lookup by `email` or `usernameKey`, exactly one `PasswordHasher.verify` (dummy for unknown or unverified), `SessionService.create` with the epoch from that lookup.
- `SessionService.create` (32 bytes from `Random`, base64url, SHA-256 stored, now + 30 days) and `delete` (`deleteMany` by id); `SESSION_TOKEN_BYTES` in `session-rules.ts`.
- shared-types: `SignInRequest`, `SignInResponse` (`expiresAt` ISO string).
- Tests: `credential.guard.spec.ts` and `sign-in.dto.spec.ts` (unit), `sign-in.integration.spec.ts` (real Postgres, `FixedClock`, `SequentialRandom`, counting fake `Argon2id`).
- Docs: `.claude/rules/api.md` "Credential routes" bullet; ADR 0015 "Built so far" plus the sign-out-before-sign-in line.
## Decisions
- 401 `INVALID_CREDENTIALS` is one constant body for unknown account, unverified email and wrong password; each costs exactly one argon2 derivation (asserted).
- 429 `TOO_MANY_REQUESTS` with `Retry-After` from `decide`; no counter reset on success (a member with one valid password could otherwise clear its per-IP count between guesses).
- Validation (400) and the `X-Client-Ip` refusal (400) happen before the limiter: no counter, no hash. They cost no argon2, so leaving them uncounted opens no brute-force path.
- Sign-out deletes the row (not a shortened expiry): revocation is immediate and the 1d cleanup has less to do. A replayed sign-out is the session 401.
- Rehash after a successful sign-in moved to slice 1c-iii (keeps this PR small).
- `AUTH_BUSY` (429) and database errors (503) propagate unchanged: never a sign-in without a counted attempt and a matching hash.
## Contracts for later slices
- Sign-up (1e) must store `email` and `usernameKey` as `normaliseIdentifier` output and refuse "@" in usernames, or the lookup misses.
- Web (1f) must send `X-Client-Ip` on sign-in and treat a 400 from sign-in as an unexpected failure (its own form validation runs first).
- Web (1f): after a successful sign-in, call sign-out with the previous token; a failure there is ignored and left to the cleanup timer (a failed sign-in must never destroy the current session). Server-side alternative for 1c-iii or 1f: an optional Bearer token on sign-in, that session deleted in the same transaction as the insert.
- Web (1f) caps the raw length of the identifier and password before any normalisation (NFC is slow on crafted input).
- Successes count toward 5 per (identifier, IP) per 15 min: 1f E2E and screenshot runs must reuse sessions or use distinct users.
- The web must never auto-retry `AUTH_BUSY` (429): the attempt was already counted.

Tests: `password-rehasher.spec.ts`, `sign-in.service.spec.ts`, 4 new cases in `sign-in.integration.spec.ts`. The rehash takes a `HashSlots` place like any hash, so under load it can refuse a later sign-in with `AUTH_BUSY`; bounded by the sign-in limits and one rehash per raise.
