# OTA-139: sign-up v3b-b (Show buttons, focus)

- Slices so far: #150 shared password rule, #151 v3b-a (confirm, checklist, gate), this PR v3b-b (`feat/OTA-139-sign-up-v3b-b`): ADR 0015 "Addendum (v3b)" decisions 5 and 6. Web only: no route, variable, dependency or error code.
- `PasswordInput` (`src/auth/password-input.tsx`, `'use client'`) is the sign-in password, the sign-up password and the confirmation: `clearOnHide`, `PASSWORD_RAW_MAX`, no capitalisation/correction/spellcheck (new on sign-in), `readOnly` while pending, and `button.au-reveal` ("Show"/"Hide" plus a hidden "password" or "confirmation", `aria-controls`, no `aria-pressed`, `aria-disabled` never `disabled`) with one `revealed` boolean (N33). `type="text"` only when revealed and not pending. The sign-up view drops from 349 to 324 lines; v3b-a's names, autocomplete values, `aria-describedby`, checklist and gate are unchanged.
- `FocusHeading` (`src/auth/focus-heading.tsx`, client): `h1 tabIndex={-1}` focused once on mount, cleanup focuses `restoreTo`. Sign-up panel uses it with `SIGN_IN_HEADING_ID` (the shell's "Welcome back" gains `id` and `tabIndex={-1}` only, N35); "Check your email" uses it plain. No focus ring on those h1s (CSS).
- Decision, submit-time type: ADR "Too simple?" accepts a revealed field being `type="text"` at the submit event; the v3b-a note said to set it back to `password` before the gate. I went with the note (security over the ADR's wording): whether a browser saves or offers a value submitted from a text field is unverified (ADR "Not verified by running"), and the safe default is to never let it see one. How: while revealed, a native `submit` listener on the form calls `flushSync(() => setRevealed(false))`; it runs before React's delegated handlers, so the gate and the action see `password`. Cost: a reveal does not survive a submit (blocked or not), so the ADR's "`revealed` survives a refusal" is moot; it still survives a hide (the field is empty then). The ADR's Too simple bullet should be amended in the PR.
- Styles: `.au-reveal` (44px target, `--space-*`/`--radius-sm` tokens, `:focus-visible` ring in `--au-focus`), `.au-page h1[tabindex='-1']:focus { outline: none }`; the two raw `gap: 6px` are now `var(--space-2)` (2px wider).
- Tests: `password-input.test.tsx` (toggle, pending, hide on submit before the form's handlers, shared hints, no value in props), `focus-heading.test.tsx` (focus once on mount, restore on unmount, missing id), view and page tests updated (Show names and `aria-controls`, pending, sign-in h1, restore to "Welcome back", check-email focus). Mutation-checked: `flushSync` removed and `type` ignoring pending both fail.
- Open Minors: bfcache restore keeps typed passwords (follow-up: `pagehide` listener emptying password inputs); a native submit before hydration still skips the gate.
- Not verified in a browser: focus and Next's route announcer on a query-only navigation and under `<Activity>`, screen-reader output of "Show password"/"Show confirmation", password managers and the type switch at submit (Chrome's `WillSendSubmitEvent` may read the form before any listener).
