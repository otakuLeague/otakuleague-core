# OTA-139 slice 1e-ii-b: resend the confirmation email

- `POST /auth/email-verification/resend` (`EmailVerificationController`, `CredentialGuard`, `no-store`), body `EmailVerificationResendDto { email }` (sign-up's `EmailAddress` rule, now exported). Shared `EmailVerificationResendRequest`/`Response` (`{}`).
- `SignUpService.resendVerification`: 403 `SIGN_UP_CLOSED` before any counter; 10 per IP per hour (`email-verification-resend`, 429 + `Retry-After`); token drawn in every branch; one READ COMMITTED transaction locks the pending account by email `FOR UPDATE`, then upserts its token with the account's own deadline copied in SQL and the binding untouched. 202 `{}` for every address; only a pending one gets a mail, after the answer. No hash, no counter keyed by the email, no write to `app_user` or the hold.
- Migration `20261120120000_auth_token_one_per_purpose`: dedupe (keeps the newest), drop `auth_token_user_id_idx`, UNIQUE(`user_id`, `purpose`). Sign-up's token write is now `ON CONFLICT (user_id, purpose) DO UPDATE` (the old delete-then-insert CTE fails with 23505 under the constraint).
- Tests: every edge case of the addendum, silent cases compared header for header with the pending one, and six forced races (confirm, resend vs confirm, re-submit, resend then re-submit, cleanup, two resends) plus a burst of five. Removing `FOR UPDATE` makes four races fail.
- Cloud run: integration on throwaway apt Postgres 16 in /var/tmp, migrations applied by psql through a scratch `pnpm` shim (no Prisma schema engine). email-verification, sign-up and auth-cleanup specs green on Node 22 (they use a fake `Argon2id`).
- Gate for production sign-up unchanged except UNIQUE(`user_id`, `purpose`), now done. Still open: per-address email budget, common-password list, keyed email hash on the hold, reserved usernames, 24 h per-email cap on unbound password guesses.
