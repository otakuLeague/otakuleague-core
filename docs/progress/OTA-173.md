# OTA-173: guard first-visit anime imports

- What changed: `ImportLimits` (`apps/api/src/anime/import-limits.ts`) caps cold imports with a global token bucket (burst 10, +1 per 20 s) and remembers not-found/adult ids for 1 h. A capped cold import answers 429 `ANIME_IMPORT_LIMIT_REACHED`; 503s are never remembered. The id route no longer bumps `lastViewedAt` (only slug page views do). Stale background refreshes take only a free AniList slot (`maxQueueMs: 0`). Web shows a calm "try again in a minute" state on 429 instead of throwing; `robots.txt` disallows `/anime/anilist/`.
- Decision (ADR 0006 addendum): keep open imports behind the cap; relation-node allowlist rejected (season selector and search open ids outside stored franchises).
- Known limits: the Railway API domain is public, so direct hits can empty the bucket for everyone; a crawler following the id→slug redirect still refreshes `lastViewedAt`. Follow-up ticket for a web→API shared-secret guard and per-visitor limit.
- Not run in the cloud: integration tests, API typecheck/lint (Prisma engines blocked); CI is the check.
