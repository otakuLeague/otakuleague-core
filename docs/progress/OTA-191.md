# OTA-191: imported flag and anime links (autopilot, 2026-11-13)

## Slice 1 (API + shared-types, ADR 0018)
- `imported: boolean` on `AnimeListEntry` and `FranchiseEntry`: true only when an `anime` row is linked to the AniList id (same link as `AnimeService.findStored`); one `IN` lookup (`findImportedAnilistIds`); manga always false.
- Web guards accept `imported` absent, reject non-booleans, and validate `related[].entries`.
- Decisions: purged anime count as not imported; OTA-192's `imported_at` must not redefine `imported`; a missing field stays tolerated (new web + old API falls back to nofollow id links).

## Slice 2 (web only, shipped)
- `animeLink(target, segment?)` in `apps/web/src/anime/anime-link.ts`: `/anime/<slug>` only when `imported === true` and slug non-null, else `/anime/anilist/<id>[/tab]` with `rel="nofollow"`.
- Season selector and home cards use it; `seasonHref` and `cardHref` removed; `prefetch={false}` kept and now tested on season links too.
- ADR 0018 accepted; architecture.md and `.claude/rules/web.md` updated.
- Decisions: plain `{ href, rel }` return; `seasonOptions()` normalises a missing flag to false at the boundary.
- Next: PR #80 (OTA-137) still imports `cardHref`; when rebased it must switch the browse card to `animeLink(entry)` or main fails typecheck. OTA-191 is complete after this PR.
