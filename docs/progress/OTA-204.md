# OTA-204: ReDoS test uses a growth ratio, not a wall clock

- The ReDoS test in `packages/shared-types/test/redaction.test.mts` no longer uses a 20 ms wall clock; a cold first call took 20.04 ms on a GitHub runner and failed CI after #104.
- New check: warm both sizes, then 25 interleaved rounds keeping the minimum for n and 4n; `time(4n) / max(time(n), 0.05 ms) < 8` (linear ≈ 4, p95 ≈ 4.5; injected quadratics ≈ 9-15x). No absolute backstop: it never fires for a quadratic at 8 KB. A busy neighbour hits both sizes alike, so interleaving keeps it stable.
- Inputs are now n ≈ 2 KB and 4n ≈ 8 KB: `redactText` truncates at 8192 chars, so the old 16 000-char inputs were already cut and a quadratic regex could hide behind the cap.
- Proven: an injected `.replace(/[\w./:"=\s-]+!/g, '$&')` (12.75x) and a `"[^\n]*"\n` alternative in KEY_VALUE (9.41x) both fail it; clean code passed 5 of 5, plus 2 of 2 with a busy neighbour.
- `docs/PROGRESS.md` not edited (open PR #109 changes it).
