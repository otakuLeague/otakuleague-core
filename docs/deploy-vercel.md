## Build command

`pnpm --filter @otakuleague/shared-types build && pnpm run build`

With a cached install, the workspace `prepare` step that builds `shared-types` was skipped, and previews failed with `Can't resolve '@otakuleague/shared-types'`. Building it explicitly makes the build independent of the install cache.

With `INTERNAL_API_KEY` set, the web sends it on every API call, and the build fails (`next.config.ts`) if the key is malformed or `API_BASE_URL` is not https: a bad value stops the deploy, never live requests. It also sends the visitor's IP (`X-Client-Ip`) on calls that can make the API call AniList for the visitor (imports, list pages; ADR 0019 OTA-195 addendum), read from `x-forwarded-for`, only when `VERCEL=1`: Vercel overwrites that header with the address it saw, so it is trustworthy only there. Keep "Automatically expose System Environment Variables" on, or no IP is sent and every visitor shares the API's `unknown` bucket, and production sign-in is off: credential calls need `VERCEL=1` and `VERCEL_ENV=production` (previews never take a password), and without `VERCEL=1` they fail with a configuration error. A CDN or proxy in front of Vercel needs its own decision first. Check after setting it: the deploy's build log is green, `/anime/<slug>` and `/` still load, and `curl -i '<api>/anime/search?q=a'` answers 403 once Railway has the key too.

## Search indexing

`beta.otakuleague.com` is the production deploy of `main`, so `VERCEL_ENV` cannot tell the beta from the future real site. Indexing is driven by one constant, `SEARCH_INDEXING` in `apps/web/src/seo/indexing.ts`, currently `'blocked'`. It sets the root `metadata.robots` in `apps/web/app/layout.tsx`, which renders `<meta name="robots" content="noindex, nofollow">`. The same constant also sends an `X-Robots-Tag: noindex, nofollow` header on all routes from `headers()` in `apps/web/next.config.ts`, because async `generateMetadata` streams the meta tag into `<body>` on anime pages and `global-error.tsx` has no meta tag.

`robots.txt` and `sitemap.xml` are generated by `apps/web/app/robots.ts` and `apps/web/app/sitemap.ts` (static pages only, ADR 0018). There is no `Disallow: /` in robots.txt on purpose: a crawler that cannot fetch a page never sees its noindex.

At the launch cutover (OTA-149): change the constant to `'allowed'`, merge, and check on the real domain, on a page that returns 200: `curl -s <url> | grep -o '<meta name="robots"[^>]*>'` shows `index, follow`, and `curl -sI <url> | grep -i x-robots-tag` prints nothing. 404 pages keep Next's own noindex.

Also at cutover: `curl -s https://otakuleague.com/robots.txt` shows `Disallow: /anime/anilist/` and a `Sitemap: https://otakuleague.com/sitemap.xml` line; `curl -s https://otakuleague.com/sitemap.xml` lists the static pages (/, /faq and the legal pages); each page's `<link rel="canonical">` is absolute on `otakuleague.com`; then submit the sitemap in Search Console (Farouk, manual).

## Rollback

1. Vercel dashboard → project `otakuleague` → Deployments.
2. Pick the last good production deployment and use Instant Rollback (or redeploy that old deployment).
3. If neither is available, revert the commit on `main` with a PR.

A rollback keeps that deployment's variables. Rolling back past an `INTERNAL_API_KEY` rotation sends the old key: see "Internal API key" in [deploy.md](deploy.md). A rollback does not undo API migrations (see "Rollback" in [deploy.md](deploy.md)).
